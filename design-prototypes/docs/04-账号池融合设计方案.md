# 账号池融合设计方案

> 2026-11-10 · 用户已认可融合方向，第一阶段已在 `feature/new-frontend-ui` 本地落地。以下保留完整方案，并在第 9 节记录本次实现与验证边界；全量摘要和运行分析仍为后续阶段。

## 1. 推荐方向

采用原型的页面层次：页头、摘要、平台标签、筛选、紧凑表格、按需详情。完整保留现有账号管理的查询、批量、平台专属操作及配置能力。

信息压缩通过合并身份信息、默认列与可选列、详情展开来完成。不要仅缩小字号，也不要把全部现有列与固定右栏挤进同一屏。

推荐「默认全宽列表，点击账号打开详情；空间足够时详情停靠右侧，否则使用抽屉」。另外两种方式的取舍：

| 方式 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 紧凑列表 + 按需详情 | 大多数时间保留列表宽度，排障时可连续切换账号 | 需要共用详情内容与选中账号状态 | 推荐 |
| 始终显示右侧详情 | 接近原型截图，可持续观察一个账号 | 未选中也占宽，容易让主表恢复大幅横滚 | 仅适合足够宽屏且用户主动固定详情 |
| 只改旧表 CSS | 改动较小 | 独立列和多行组件仍撑宽撑高，无法达到设计的信息层级 | 不作为最终效果 |

## 2. 页面结构

```text
账号池                              导入  刷新  自动刷新  工具  添加账号
匹配账号 / 可用 / 受限 / 异常 / 已暂停 / 并发     [明确统计范围]
全部  Claude  OpenAI  Gemini  Grok  Antigravity  更多平台
搜索账号   已生效筛选标签   添加筛选                          列设置
[选中后：已选 N 项 / 全选筛选结果 / 编辑 / 刷新 Token / 恢复 / 更多]
┌─────────────────────────────────────┬────────────────┐
│ 账号 / 状态 / 容量 / 配额 / 今日 / 优先级 / 调度 / 操作 │ 按需账号详情 │
│                                       │ 配额与容量     │
│ 默认全宽；用户打开可选列后允许表格内部横滚       │ 今日费用与用量  │
│ 名称与操作列保持可见                        │ 状态原因与资源  │
└─────────────────────────────────────┴────────────────┘
分页与每页条数
```

页头唯一主按钮为「添加账号」。导入与刷新为次要操作。刷新列表、刷新 Token、刷新用量/配额保留各自名称与触发，不用一个含糊的「批量刷新」代替。

「工具」只放 CRS 同步、导出、错误透传规则、TLS 指纹模板、批量更新筛选结果；「列设置」独立，解决当前更多菜单过长的问题。导出按钮随选择明确写为「导出已选 N 项」或「导出筛选结果」。

## 3. 主表如何紧凑，同时保留信息

### 默认列

| 列 | 默认展示 | 展开或其他入口 |
|---|---|---|
| 选择 | 行勾选与当前页全选 | 保留滑选、跨页选择、全选所有筛选结果 |
| 账号 | 名称、平台 / 认证类型；下一行邮箱或 ID，必要的套餐 / Privacy / Compact 标记 | 完整平台元信息、父子账号关系；站点主页改为独立外链图标，名称始终打开详情 |
| 状态 | 主状态 + 最相关原因 / 恢复时间 | 多模型限流、积分状态、全部错误与临时不可调度原因 |
| 容量 | 并发当前值 / 上限；其他限制触发时提示 | 5h 费用窗口、会话、RPM、本地日 / 周 / 总额度全部保留；可选完整容量列 |
| 配额 / 用量窗口 | 平台真实支持的主要窗口、数值与重置时间 | 5h / 7d、多模型 / 请求数 / Token / 金额等全部窗口；保留来源与更新时间 |
| 今日统计 | 账号计费、用户扣费，辅以请求 / Token | 完整统计与标准费用；不能将两个金额合成无标签的美元数 |
| 优先级 | 继续支持现有行内增减与保存 | 编辑中仍有完整配置；保留失败回滚 |
| 调度 | 开启 / 关闭开关 | 解释当前未被调度的原因；开关开启不等于当前可用或正在接请求 |
| 操作 | 测试、编辑、更多；符合资格时可露出刷新 Token | 删除与平台专属动作进更多菜单，保留原有确认与资格判断 |

常见行以约 56–72px 为目标；带费用与多窗口的行允许更高。先压缩重复标签与信息层级，再调整行高和虚拟列表估算值。原型 44–56px 不能作为必须裁切全部内容的硬限制。

可选列继续包括：独立平台 / 类型、ID、分组、完整容量、代理、调度分数、计费倍率、上游声明倍率、创建 / 过期 / 最近使用、备注。原列的排序与用户保存的可见性不能消失；默认列方案只应用于没有既有偏好的用户，并提供主动切换到新预设的入口。

今日统计改为默认可见属于新预设。已有用户明确隐藏的列不强制恢复。需要更窄布局时，可由「调度视图 / 完整列」预设控制展示，不能静默丢弃用户选择。

### 四个容易混淆的语义

1. **容量不只是并发。** 当前 `AccountCapacityCell` 同时表达窗口费用、会话、RPM 与账号额度，必须保留完整入口。
2. **账号状态与调度开关分开。** 正常账号可以被手动关闭调度；开关开启的账号也可能 Token 失效或冷却。部分模型限流只标为部分受限，不能说整个账号已摘除。
3. **优先级、负载因子、计费倍率、上游声明倍率分开。** 原型中的「优先级 / 权重」不能把 `rate_multiplier=0.8` 当调度权重。首版列名直接用「优先级」，其他数值保持真实名称。
4. **未配置、未知、加载失败与零不同。** 未提供配额不画 0% 或 100%；缺并发 / 统计数据不表现为空闲或没有用量；历史探测值保留过期和失败标记。

## 4. 保留原有查询、工具和操作

| 现有能力 | 新位置 / 行为 |
|---|---|
| 平台筛选 | 动态平台标签；更多平台入口使用真实平台目录，不固定为原型六个平台 |
| 搜索、类型、状态、Privacy、分组（含未分组） | 搜索常驻；其余在筛选面板，生效条件为可单独移除的标签；保留 Privacy 的未设置 / Privacy / CF / Fail |
| 服务端排序、分页、每页条数 | 延用现有参数与持久化；隐藏排序列时仍可恢复，不改为当前页前端排序 |
| 监控页带范围跳入账号页 | 继续消费现有路由 query，筛选标签真实反映带入条件 |
| 手动刷新、5 / 10 / 15 / 30 秒自动刷新、倒计时 | 顶部独立控件；保留 ETag、增量合并、静默期、交互保护与待同步提示 |
| 单行测试、图片 / Compact 测试、编辑 | 保留现有完整弹窗；不因改成详情侧栏而减少字段和场景 |
| 查看统计、定时测试、复制账号 | 详情与更多菜单；保留原有资格与防重复点击 |
| 刷新 Token、重新授权、设置 Privacy、创建 Spark 影子 | 仅对符合平台 / 类型 / 母子账号资格的对象开放 |
| 恢复状态、重置本地配额、配额查询 / 刷新 / 重置 | 分开命名，继续调用原有动作与确认流程；恢复状态不能暗示只是清掉一条提示 |
| 代理回退状态与恢复原代理 | 详情代理区、代理可选列；保留过期状态与原代理信息 |
| 上游倍率单个 / 批量探测 | 详情、上游倍率可选列、批量条更多操作；保留可信度 / 有效期与最多 20 个的现有批量约束 |
| JSON 多文件导入、CRS 同步预览、OAuth / Codex 导入流程 | 延用完整现有入口和表单；导入置顶，CRS 放工具 |
| 导出已选或筛选结果，包含代理选项 | 工具 / 批量入口；保留确认、现有二次验证、影子账号跳过数量反馈 |
| 错误透传规则、TLS 指纹模板 | 工具的独立配置区 |
| 新建 / 编辑中的全部平台高级配置 | 首阶段完整复用 Create / Edit；不在视觉改造中重写或删减已有配置 |

原型「按分组 / 按平台 / 按代理分桶」和「优先级 ≤ 10」是额外需求。若只是新增 UI 后筛当前页，会产生不完整结果。第一阶段保留现有平台 / 分组过滤；分桶和优先级范围需服务端契约后再做。

## 5. 批量操作必须保留两种范围

- **编辑已选 N 个账号**：操作固定 ID 快照，支持跨页选择。选中后出现紧凑批量条；保留刷新 Token、清错误、启停调度、批量编辑、探测、删除及部分失败反馈。
- **批量更新筛选结果 N 个账号**：无需勾选，从工具进入。打开时冻结筛选条件，预览匹配数量，提交仍按该范围。不能替换成编辑当前页，也不能与已选操作混用文案。

表头全选当前页之后，提供「选择全部 N 条匹配结果」。筛选变化取消旧的全选请求和选择，翻页继续保留已选 ID。请求失败保留原选择；批量部分成功保留失败项。

「设置并发 / 分配代理」可作为批量编辑的快捷入口，打开原 `BulkEditAccountModal` 并定位相关字段，其余高级编辑能力仍完整可达。跨页混合平台资格不能仅凭当前页或前 100 条样本判断，后续应由后端返回完整范围元信息或采取保守展示。

## 6. 详情面板

抽出一份共用的详情内容，桌面停靠面板与抽屉复用同样的数据和动作。推荐分为：

1. 身份与状态：平台 / 类型、套餐 / Privacy / Compact、邮箱 / ID、母子关系、错误原因与恢复时间。
2. 配额与容量：真实窗口、重置时间、数据来源、并发 / 会话 / RPM / 金额限制、日周总额度。
3. 今日用量：请求、Token、账号计费、用户扣费；统计详情继续使用现有入口。
4. 调度与资源：开关、优先级、负载因子、分组、代理及回退、到期自动暂停、计费倍率 / 上游声明倍率、日期、备注。
5. 快捷动作：测试、编辑、符合资格时刷新 / 重新授权；其他动作复用菜单。

当前临时不可调度入口支持**查看原因与重置**。原型「临时摘除」若需要设置一个新的暂停时长，须另外定义时长、恢复、权限和后端接口，不能把现有原因弹窗包装成已支持的一键摘除。

默认不选中第一行，也不永久预留空白右栏。打开、关闭与连续切换详情不改变复选框选择，不丢分页 / 排序 / 滚动位置。名称改为统一详情入口，同时保留 API Key 站点主页的独立安全外链。

响应式以侧栏右侧的**实际可用宽度**决定：桌面足以容纳主表和 360–420px 详情时才停靠；不足时用现有抽屉，避免为了常驻面板挤爆表格。视口小于 1024px 延用已有账号卡片模式，手机详情全宽。冻结身份和操作列，选开很多可选列时仅表格内部横滚。

## 7. 原型哪些数字现在能实现

| 项目 | 当前情况 | 落地办法 |
|---|---|---|
| 筛选结果总数 | 列表 `total` 可直接用 | 明确标为「匹配账号」，有筛选时不写成全站账号数 |
| 可用 / 受限 / 异常 / 暂停 | 当前 `AccountPoolSummary` 只统计当前页 | 第一阶段显著写「本页」；完整设计补与列表共享筛选的全量摘要 |
| 并发占用 | 当前逐行 runtime 数据并在前端求本页之和 | 全量汇总需后端支持；当前并发读取失败会补 0，需补未知 / 部分成功标记 |
| 平台计数 | 当前平台标签没有计数 | 后端返回 facets；应用其余筛选，排除平台本身条件，翻页不改变平台计数 |
| 今日请求 / Token / 两类费用 | 已有批量今日统计 | 复用当前页批量请求；「今日」沿用服务端自然日，避免误当最近 24 小时 |
| 配额、余额、重置时间 | 多平台能力不同，已有 usage 与快照 | 复用平台适配；不把本地配额、上游额度、模拟估算混作同一口径 |
| 上游声明倍率 / 探测时间 | 部分 API Key 账号已有 | 复用探测快照，保留不支持、未探测、过期、失败及同步状态 |
| 今日调度切换 | 运维有平台 / 分组数据，账号页没有匹配全部筛选的契约 | 第一版不展示；补事件定义与范围后接入 |
| 池健康分 | 运维健康分含 SLA、系统及后台任务，不等于账号池健康 | 第一版省略；不能借用运维健康分或生成装饰性分数 |
| 单账号成功率、首 Token、小时趋势、并发持续时长 | 账号 stats 只有用量、每日历史与总耗时等；无等价契约 | 后续新增按 account_id 的运行分析，并定义重试与分母；不把平均总耗时标成 TTFT |
| 代理延迟 / 地区 | 可来自代理管理最近测试缓存，账号内嵌代理字段不完整 | 按需关联真实缓存并标「最近测试」；`/admin/proxies/:id/stats` 当前为 mock，不能接入 |

全量摘要建议独立于分页列表，分享同一筛选解析和派生状态规则，响应包含 `scope`、`as_of`、完整性状态和各指标错误。摘要严格应用当前列表全部筛选；平台 facets 仅排除平台本身条件，并在接口契约中说明。冷却可能在两次采集之间自然结束，不能承诺分开请求始终瞬时一致。

四类摘要是互斥的 UI 状态概括，不能冒充网关所有模型的最终调度资格。若点击摘要要筛选这四类，应增加匹配同一规则的服务端派生状态条件；不能把「可用」直接映射为 `status=active`。

只读展示使用现有详情 / usage / 快照读取。`clear`、`recover`、`reset` 属于写操作；尤其 OpenAI 配额重置消耗不可退款重置券，不能将这些端点当成详情初始化或额度查询来源。原 `02-设计规范与实现映射.md` 中把 reset-credits 作为配额来源的描述不适合作为实现依据，以本节核对为准。

## 8. 实施顺序与验收

### 第一步：列表和入口融合

复用 `AccountsView` 的请求、选择和操作处理，调整身份列、默认列、行密度、筛选标签、独立列设置与工具菜单；完善已有详情内容。保留轻量列表、按需详情、批量 Usage / 今日统计与昂贵指标按需请求。摘要继续明确本页口径。

验收：旧功能都有明确新入口；优先级仍可编辑；Privacy / CF / Fail、全选、批量范围、平台 / 影子资格、代理恢复、导入导出流程全部可达；已有列偏好保留。新建和编辑不因视觉调整丢凭据或高级字段。

### 第二步：全量摘要和详情数据

新增共享筛选的摘要 / 平台 facets；补并发与统计完整性状态；详情复用同一用量缓存和数据源，避免每行独立拉多组接口。详情常驻后重审刷新暂停规则，不能因为「详情打开」让整页永久停更，也不能让自动刷新打断编辑。

验收：同条件翻页不改变全量摘要；筛选与平台计数范围正确；查询失败显示未知；快速切换账号无旧响应覆盖；日期 / 时间口径明确。

### 第三步：运行分析增强

需要时再接入单账号成功率、TTFT、最近小时趋势、调度切换和新临时暂停能力，先确定事件范围、采样覆盖和权限。保留功能等价的前两步不依赖这一阶段。

后续实现检查：受影响账号页 / 选择 / 批量 / 用量 / 菜单测试、类型、lint、国际化、构建；浏览器核验窄屏卡片、标准桌面、宽屏详情、深色、大页数虚拟列表、自动刷新中编辑、部分失败。沿用 `pnpm --ignore-workspace`，类型构建与 Vite 分开执行。

## 9. 第一阶段实施记录

本阶段已经实现紧凑身份列、动态平台标签、筛选面板与可移除条件、独立列设置、工具菜单、选中操作条及共享账号详情。名称打开详情，站点主页保留独立安全外链；优先级继续行内编辑，调度继续独立开关。新用户默认合并平台信息并展示今日统计，已有列偏好和明确开启的调度分数保留。

详情与列表共用真实账号组件及元信息解析，完整展示容量、多窗口配额、两类今日费用、分组、代理回退、倍率和日期。外层内容区宽度达到 1520px 时采用主表与 380px 详情两栏；不足时复用抽屉，移动端保留账号卡片。常驻详情不永久暂停刷新，抽屉进入另一个弹窗时先关闭，避免焦点冲突。详情请求按 ID 共享，并处理快速切换、返回仍在加载的账号及关闭后的迟到响应。
