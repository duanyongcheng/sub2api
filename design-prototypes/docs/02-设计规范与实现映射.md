# Sub2API 重设计 · 设计规范与实现映射

> 配套文件：`01-前端菜单与功能点分析.md`（信息架构与功能清单）、`../*.html`（可交互原型）
> 目标：让工程同学能**按原型 1:1 落地**，并知道每个区块对应哪个接口。

---

## 1. 设计原则（先立规矩，再画界面）

| 原则 | 说明 | 落到界面上的表现 |
|---|---|---|
| **一屏一决策** | 每个页面只回答一个问题 | 页面顶部固定为「标题 + 一句目标 + 1 个主操作」，其余进次要按钮或 `⋯` |
| **异常优先** | 运营/用户最关心的是「哪里不对」 | 概览页把「需要处理」放在 KPI 之上；监控页把降级行标黄标红 |
| **数据可推导** | 所有数字都带口径 | 费用一律写「实际 / 标准」；成功率标注「排除限流」；金额标注币种 |
| **表格即工作台** | 列表页是最常停留的界面 | 行高 44–56、悬停才露出操作、关键状态用 pill、进度用内联细条 |
| **克制用色** | 主色只用于「可点击 / 当前 / 主操作」 | 语义色只在状态 pill、进度条、警示条出现 |
| **深浅同构** | 深色不是反色，是同一套语义 token 的换值 | 所有颜色走 CSS 变量，组件不写死 hex |

### 2.1 颜色

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--p-500/600` | `#14b8a6` / `#0d9488` | 同 | 主色（沿用现有 Tailwind teal 色阶） |
| `--p-50` | `#f0fdfa` | `rgba(20,184,166,.12)` | 选中项 / 主色底 |
| `--bg` | `#f6f8fa` | `#070b12` | 页面底色 |
| `--surface` | `#ffffff` | `#0d1420` | 卡片 |
| `--surface-2` | `#fbfcfd` | `#111a28` | 表头、内嵌块 |
| `--surface-3` | `#f1f5f9` | `#16202f` | 输入底、分段控件底 |
| `--border` | `#e8edf2` | `#1d2838` | 常规描边 |
| `--border-strong` | `#d9e1ea` | `#2a374a` | 输入框描边 |
| `--text` | `#0f172a` | `#e8eef6` | 主文本 |
| `--text-2` | `#475569` | `#a4b2c5` | 次级 |
| `--text-3` | `#8a97a8` | `#6b7b90` | 辅助/占位 |

语义色（浅/深底色 + 文本色）：

| 语义 | 主色 | 底 | 文本 | 使用场景 |
|---|---|---|---|---|
| 正常 OK | `#10b981` | `--ok-50` | `--ok-600` | 可用、已完成、达标 |
| 警告 WARN | `#f59e0b` | `--warn-50` | `--warn-600` | 限流、降级、毛利预警、待履约 |
| 危险 DANGER | `#ef4444` | `--bad-50` | `--bad-600` | 异常、失败、亏损、成本倒挂 |
| 信息 INFO | `#3b82f6` | `--info-50` | `--info-600` | 进行中、同步、订阅 |
| 特殊 VIOLET | `#8b5cf6` | `--violet-50` | — | stream 类型、Grok 平台 |

> **平台色**（固定，不要改）：Claude `#d97757`、OpenAI `#10a37f`、Google `#4285f4`、Grok `#8b5cf6`、Antigravity `#0ea5e9`、国产模型 `#f97316`。平台色只出现在 26×26 的 `.plat` 方块和流量条形里。

### 2.2 字体与排版

- 字体：`-apple-system / Inter / PingFang SC / Microsoft YaHei`，数字统一 `font-variant-numeric: tabular-nums`。
- 字号阶梯：页面标题 21px/700 · 卡片标题 14px/650 · 正文 13px · 表格 12.4px · 辅助 11.5px · 微型标签 10.5px/700 大写间距 .06em。
- 大数字（KPI）：25–27px / 720 / 字距 −.03em。

### 2.3 间距与圆角

- 间距基数 4px；页面内边距 `22px 24px`；卡片间距 16px；栅格间距 14–16px。
- 圆角：输入框/按钮 10px · 卡片 14px · 大容器 18px · 徽标 999px。

### 2.4 阴影

`--sh-xs`（卡片默认 1px 描边+微阴影）→ `--sh-md`（悬浮）→ `--sh-lg`（抽屉/弹窗）。**不要给普通卡片加彩色阴影**，主按钮除外（`0 6px 16px -8px rgba(13,148,136,.9)`）。

## 3. 组件规格

| 组件 | 规格 | 现有代码对应 |
|---|---|---|
| **侧边栏** | 248px，分组标题大写 10.5px；选中项 = 主色底 + 主色文字 + 左侧无竖条（避免与折叠态冲突）；底部放「额度进度 + 主题切换 + 收起」 | `AppSidebar.vue`（建议拆分：`NavGroup` / `NavItem` / `SidebarMeter`） |
| **顶栏** | 64px，内容 = 页面标题/副标题 + 全局搜索（⌘K）+ 通知 + 余额胶囊 + 用户菜单 | `AppHeader.vue` |
| **KPI 卡** | 标题 12.2px + 数值 25px + 变化率 pill + 右下角 sparkline（108×46） | 新增 `KpiCard.vue`（替换现在手写的 `card p-4`） |
| **数据表** | `table-layout: fixed` + `<colgroup>` 精确列宽；表头 10.8px 大写；行高 44；首列可粘性；操作列固定 96–168px | `DataTable.vue` + `TablePageLayout.vue` |
| **状态 Pill** | 高 22px，圆角 999，前置 6px 圆点；5 档语义 | 统一替换 `StatusBadge.vue` 的 4 处散落实现 |
| **进度条** | 6–8px，圆角 999；≥80% 转警告色、100% 转危险色 | `SubscriptionProgressMini.vue` 可复用逻辑 |
| **内联输入（定价表）** | 74×27，聚焦时主色描边 + 2px ring | 新增 `InlineNumberField.vue` |
| **抽屉** | 右侧 360–520px，`shadow-lg`，底部固定操作区；**替代 90% 的模态框**（账号详情、密钥详情、事件详情） | `BaseDialog.vue` 增加 `variant="drawer"` |
| **弹窗** | 仅用于「不可逆操作」（退款、恢复备份、清空数据）：宽 560，底部浅底操作条，危险操作红色实心 | `BaseDialog.vue` |
| **警示条** | 16px 图标 + 1–3 条可点击条目 + 右侧时间 | 新增 `ActionStrip.vue` |

## 4. 导航重构（与现有代码的差异）

### 4.1 用户侧：12 项 → 4 组 12 项

保留全部功能，仅按业务语义分组（工作 / 服务 / 账务 / 账户），并在「API 密钥」上显示数量徽标、「渠道状态」显示实时可用率。

### 4.2 管理侧：22 项平铺 → 5 组 18 项 + 6 项「我的账户」

| 新分组 | 菜单 | 合并/调整说明 |
|---|---|---|
| 总览 | 概览、运维监控 | 「运维监控」带异常数徽标（替代静态菜单，告诉管理员「有事」） |
| 流量 | 账号池、分组与定价、渠道定价、渠道监控 | **取消「渠道管理」折叠组**（只有 2 项，浪费一次点击）；「账号管理」更名「账号池」并显示总数 |
| 客户 | 用户、订阅、订单、支付配置、兑换码/优惠码、邀请返利 | 「兑换码 + 优惠码」合并为一项双 Tab；「订单管理」折叠组三页合并为「订单」页内 Tab（概览/列表/套餐） |
| 系统 | 安全审计（内容审计 + 提示词审计双 Tab）、操作日志、插件、系统设置 | 保持折叠组，但只在组内 ≥3 项时折叠 |

> 代码改动点：`AppSidebar.vue` 中 `adminNavItems` 的数组重排 + 增加 `badge` 字段；路由本身**不需要改**（原型中的合并页用同一路由内的 Tab 呈现）。

## 6. 落地建议（按性价比排序）

1. **先做 Token 层**：把 `style.css` 里的散落色值收敛成 CSS 变量（含深色），预计可删除各页面 40% 的 `dark:` 手工旁路。
2. **抽出 4 个基础组件**：`KpiCard`、`StatusPill`、`PageHeader`、`ActionStrip`。改造 10 个页面即可见效。
3. **表格规范统一**：给 `DataTable` 增加 `fixed` 布局与 `columns[].width`，解决「列被挤爆」问题（账号池、密钥页最明显）。
4. **抽屉化**：`BaseDialog` 增加 `variant="drawer"`，优先迁移「账号详情 / 密钥详情 / 事件详情 / 用户详情」。
5. **导航重排**：只改 `AppSidebar.vue` 的数组与分组，零风险，视觉收益最大。
6. **概览页重组**：把「待办 / 异常」置于 KPI 之上，是本次重设计中业务价值最高的一处改动。
