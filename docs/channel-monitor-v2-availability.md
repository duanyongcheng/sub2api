# V2 服务状态与可用率数据

V2 真实流量监控在服务状态页展示分组与平台的可用率矩阵，复用现有可用率组件。V1 主动探测、配额监控及系统默认模式不变，不需要部署 Relay Pulse 服务。

## 使用

- 监控展示统一位于 `/monitor`：V2 模式下仅展示「服务状态」，移除「可用率监控」页签。旧链接 `/monitor?view=availability` 同样展示服务状态。V1 模式保留原主动探测状态页。
- 普通用户通过用户 API 查看有权限的分组，隐藏绝对请求量和内部错误样本；管理员通过现有管理员 API 查看监控配置范围内的运营数据、错误次数和代表样本。同一页面的所有区域使用一致的角色与筛选范围。
- 「服务状态」采用与可用率矩阵一致的紧凑列表：名称、可用率、平均首字延迟、状态时间条与服务端健康分对齐展示，模型明细按需展开。窄屏将身份、指标与时间条分行；状态色仍依据用户端 `health.error_rate`，不套用管理矩阵的固定百分比档位。
- 桌面矩阵主行约 38px、模型子行约 32px，名称和平台同行显示；收窄名称与指标列，把更多宽度留给时间条。时间条为 20px 高、格间距 2px，表头与图例同步收紧。长名称保留完整提示，展开模型、键盘操作和区间提示沿用现有行为。
- `/admin/channels/monitor` 只管理监控配置：V2 模式默认进入「V2 数据监控配置」，V1 模式默认进入探测项管理。可用 `?tab=v2`、`?tab=legacy` 直达对应配置；探测项、模板和手动检测仍在这里管理。
- 服务状态页为用户展示页面，所有角色均不显示「监控设置」入口，也不保留上方操作空行；配置在独立管理页进行。配置页的「查看监控」统一返回 `/monitor`。
- 全宽是所有使用 `AppLayout` 页面的默认布局：主体铺满侧栏右侧的可用内容宽度，只保留正常响应式边距，不再保留统一的 1440px 居中上限。服务状态页直接使用该默认布局。
- 默认窗口为 24 小时，可选 90 分钟、7 天、30 天；供应商支持多选，维度支持平台、平台 / 分组、平台 / 模型及平台 / 分组 / 模型。展示方式可选卡片、紧凑矩阵、趋势和列表，默认紧凑矩阵。
- 顶部指标卡展示可用率、错误率、首 Token P50（附 P95）、吞吐、缓存率和样本覆盖。吞吐为现有 TPM ÷ 60，普通用户遵循隐藏吞吐开关；不把它解释为单次请求的生成速度。样本覆盖为所选窗口中样本达标的时间片 / 全部预期时间片，独立于历史回填完成度。
- 异常排行展示最多五个有足够样本且有错误的模型，管理员按错误次数排列，普通用户按错误率排列；点击模型可筛选对应平台和模型。错误原因分布和原始首 Token P50 / 错误率趋势遵循相同时间及筛选范围，未知时间片保留空洞。
- 不接入告警、邮件通知或用户侧展示开关面板。新增功能直接位于服务状态页，不恢复原「可用率监控」页签。
- 目录、模型排行和错误分布各自显示加载或失败状态，辅助模块失败不清空已成功的矩阵；可单独重试。切换展示方式复用数据，切换筛选会取消过期请求。

## 保留的可用率组件

`AdminMonitorBoard`、`ChannelStatusV2View` 及相关可用率组件继续保留，供共享展示组件与后续维护使用；`/monitor` 不再挂载这两个视图。以下记录这些组件原有的能力和数据边界。

- 管理员看板另提供「真实流量 / 探测记录 / 全部证据」视图。探测记录来自现有 `GET /admin/channel-monitors`，只展示最近保存的 V1 结果，不合并进真实流量结论；当前 API 尚无探测项 `group_id`，因此不会用分组名称推测绑定。
- 管理矩阵使用独立的离散可用率档位：≥99% 正常、90–99% 波动、<90% 异常；无流量或样本不足为灰色。后端 `health.*` 阈值与分数保持原样，分数只作第二层信息。
- 点选矩阵色块时，管理端可传 `start` / `end` 固定查询原窗口或完整对齐的聚合区间；该参数只接受管理员请求，并受所选窗口跨度和对应桶保留期限制。用户端仍只用预设相对窗口。
- 支持按平台、平台/分组、平台/模型、平台/分组/模型查看，以及卡片、列表、原色块矩阵和折线图。
- 平台筛选支持多选；卡片/列表顶部的「总体状态」栏提供搜索（含展开子项）、异常优先/名称/可用率排序、只看异常和全部展开。
- 展开后每个子项（模型或分组）显示可用率、平均首字延迟和迷你状态条；子项按异常优先排序，「其他模型」排在最后。列表视图的子项与主行共用列，数值上下对齐。
- 错误原因分「计入可用率」「已忽略」两栏，条形按当前列表最大占比等比缩放，数字仍是绝对占比；样本消息只对管理员显示。

## 添加 DeepSeek 等供应商

V2 的早期数据库默认配置只启用了六个平台。采集器支持其他平台，但未配置或未启用的平台不会被监控查询返回。

1. 在「V2 数据监控配置」→「平台与模型」中单独添加 DeepSeek，或点击「一键补齐供应商」。
2. 确认所需平台已启用；模型列表留空表示展示所有真实模型名。
3. 保存配置。供应商存在可见分组和真实流量后即可在监控页查看；无流量或样本不足显示灰色，不显示虚构的 100%。

补齐操作只添加统一平台目录中缺少的条目，**不重新启用已有禁用平台、不覆盖模型名单或分组范围**，保存前不会改变服务端配置。没有修改历史迁移或静默扩大展示范围。

## 数据契约与维护注意事项

- 新界面复用 `GET /[admin/]channel-monitor-v2/{snapshot,matrix,models,dimensions,errors}`，没有新增 API 或数据库字段。
- `matrix?group_by=platform_group` 等服务端聚合行提供卡片主指标；另取 `platform_group_model` 子行用于展开。平台汇总的子项使用 `platform_model`。
- 可用率为 `1 - metrics.error_rate`，但只有 `health.error_rate !== 'unknown'` 才显示数值。不能按前端 `request_count` 判断是否有数据：用户端请求量可能已被脱敏为零。
- **不对模型百分比求平均**；使用服务端计入请求加权的窗口结果。窗口可用率按现有 V2 口径计算，不改成 Relay Pulse 的「仅累加样本达标桶」口径。
- 卡片及时间条按 `health.error_rate` 着色，不使用包含缓存/延迟的综合评分。平均首字延迟使用 `ttft.avg_ms`，按同一阈值中的 TTFT 预算独立着色，而非把 P50 的评分标在 AVG 上。
- 时间条覆盖 `[coverage.requested_start, coverage.requested_end)`；历史未覆盖、无流量、样本不足为灰色。缺少 `requested_end` 的旧响应回退 `data_through`。
- 主时间条是一个 Tab 停留点，方向键 / Home / End 切换格子，悬停或聚焦时以浮层显示明细，不改变卡片高度；子项迷你条不可聚焦，只提供原生 title。
- 搜索/只看异常是卡片展示过滤；顶部 KPI、「总体状态」计数和错误分类仍基于平台/分组/模型 API 筛选范围。
- 自动刷新和切换筛选期间保留旧卡片并淡化显示；仅手动点击刷新时显示骨架屏。
- 供应商名称与选项来自统一平台目录；未知平台保留原名称并使用中性色，不在组件内维护另一份固定名单。
- 快速切换筛选和明细标签时，过期响应不得覆盖当前状态；离开页面取消未完成请求，隐藏标签页暂停轮询。

## 验证

页面入口测试位于 `frontend/src/views/user/__tests__/ChannelStatusView.mode.spec.ts` 和 `frontend/src/views/admin/__tests__/ChannelMonitorView.configuration.spec.ts`，验证仅挂载服务状态、旧链接兼容、各角色均无配置入口、全宽布局及 V1 配置行为。服务状态与矩阵测试位于 `ServiceStatusView.spec.ts` 和 `ServiceGroupCard.spec.ts`。

保留的共享组件测试位于 `frontend/src/features/channel-monitor-v2/__tests__/AvailabilityBoard.spec.ts`、`MonitorSettingsPanel.spec.ts`、`frontend/src/views/user/__tests__/ChannelStatusV2View.availability.spec.ts`，覆盖：

- 脱敏请求量仍能显示真实可用率、样本不足不显示 100%。
- 汇总不平均子项百分比，DeepSeek 及未知供应商展示、跨平台子项隔离。
- 状态时间条补空、键盘提示与方向键切换、子项迷你条、卡片/列表、搜索、排序及只看异常。
- 子项按父行未展示的维度命名，「其他模型」排在最后。
- 错误样本权限与忽略分类。
- 补齐供应商保留已有禁用状态、模型及分组配置。
- 用户/管理员 API 分流、筛选请求竞争，以及原 V1 模式与刷新行为。
